# Token AMP phases in the existing Runtime owner

The fixed-arena component audit is closed. The next change binds its event
schedule to the actual ReferenceCompilerRuntime, including independent
initialization, original causal source records, pre-target identities,
revealed targets, pending gradients and atomic learner publication. It does
not add a semantic architecture action or change Foundation/ERC.

## 1. The phase invariant

`TokenCudaPrefixContract` registers the same `TokenInitializer` as native
construction, the fixed v2 event/carry schedule, explicit arena storage,
numerical tolerances, primitive/rounding allowances and retained frame size.
A different Gamma, foreign representation, likelihood lowering or inherited
installation release refuses. Token search, persistence, installation and
automatic policy remain unregistered; their old explicit refusals stay.

The implementation is `fp_reference/token_cuda_prefix.py`, called from the
existing private `_CudaPrefix` through the existing paid Runtime hook. It
uses the existing arena, host/device binding, immutable phase frames and
atomic publication. There is no alternate Runtime or helper-issued authority.

The complete physical record contains one integer master origin, prepared
half coefficients and readout operands, every actual event leaf and source/
target record, all binary-carry blocks with their interval sizes, and the
current gradient basis. `token_cuda_state.py` encodes actual initialized
arrays as immutable dtype/shape/word bytes. Leaves refer to the one enclosing
origin; they do not each duplicate the full model. This is a lossless
encoding of the registered sharing, not erasure of an old origin or cache.
The current basis never replaces the forests. Every retained device view
stays readable and old extents are not reused.

Initialization executes registered Gamma independently from the declared
patterns; no trained reference endpoint supplies an AMP successor. On each
later phase, fresh actual predecessor words must equal the owner's immutable
accepted record. Observation additionally requires the exact pre-target
phase, observation identity and physical predecessor. Runtime passes the
original owned source context after its work charge; reference records and
the actual target must agree. Profiles preserve original source positions
while their learner clock resets and later attaches at a whole-unit boundary.

For a newly executed phase, a CPU interpreter starts from those complete
accepted predecessor words and executes only the new operation graph. It
checks binary32 decisions with the existing binary64 enclosure/exact-cell
decoder. A half product has at most22 significand bits, and a sum/difference
of finite half numbers spans at most41 bits, so those real intermediate
operations are exact in binary64 before the specified half rounding. Integer
casts beyond the exact binary64 integer domain refuse. The pinned rounding
and gradual-underflow assumptions remain explicit; no unconstrained NumPy
or Torch endpoint is treated as exact native arithmetic.

Every actual new array word must match this checked graph, including integer
indices and shifts. The resulting complete cache/state must match it too,
and old states and forecasts are reread after execution. Induction therefore
extends the already validated leaf intervals and trees without replaying all
earlier derivatives. A current-gradient comparison alone remains insufficient.
Native pending-gradient enclosures are currently recomputed for the complete
coordinate relation; this is still a cost, not a claim of linear training.

## 2. Numerical relation and its exact scope

The existing complete master/gradient predicate compares every native
coordinate, including corrected readout gradients consumed by the commit.
The existing all-label envelope compares the fixed positive mass recipe,
its mathematical normalization and the separately rounded division by the
stored normalizer. `Kernel._label_mass` is now shared by actual target
observation and the separately paid arena `readout_label` method. This binds
the envelope to the actual registered code rather than borrowing the passive
Torch helper's identity. Unqueried labels are covered by that conditional
recipe theorem; their division words are not claimed to have been executed.
The existing normalization distinction is retained: rounded divisions need
not sum to one. Persistence probability decoding remains unregistered.

The exact checked class is one owned phase over its actual complete
predecessor, declared code, original context and (for observation) revealed
target, subject to the registered numerical/resource bounds. A checked prefix
does not certify arbitrary future inputs, an exhausted architecture class,
fresh statistical persistence, installation or model quality. There is no
new `CERTIFIED_COMPLETE` claim. Insufficient cells, integer/rounding evidence,
tolerance or resources returns UNRESOLVED through the existing failure path;
actual target/data use and executed costs cannot be rolled back.

The exclusive journal is `evidence/minimal/FP_TOKEN_CUDA_OWNER_A1.json`;
the launcher is `scripts/run_token_cuda_owner_audit.py --run`. Source must be
clean and committed. Each child starts suspended and joins its fixed Windows

attempt; failure stops the suite and is retained without silent retry.
