# RN-2: prospective relation models with unresolved training optimization

Preregister before target model execution. This experiment follows the
[RN-1 negative result](../relation_noise/RESULTS.md) and the
[owned prospective selection argument](../../theory/proofs/OWNED_PROSPECTIVE_SELECTION.md).
It changes the registered Compiler strategy, using the same FP semantic
grammar, reachable initializer values, numerical paths and resource contract.
Foundation R4, XVII.31 and ERC-1 remain frozen. Execute only after the expanded
CPU/CUDA strategy's endpoint audit passes; the old release alone does not
authorize an unexecuted strategy.

## 1. Scientific question and fixed cases

Can useful native models be constructed and prospectively installed while
their full training-optimization class remains honestly unresolved? Does the
change work on previously unexecuted seeds, beyond the known RN-1 failures?
Neither installation nor empirical class completion identifies unknown
relations or proves a population-optimal model.

There are twenty FP cases:

* Diagnostic cases: n=8 and 16 with IID seeds 0,1,2,3; the conditioned seed0
  at both sizes; and the two original n=8 disconnected seed0 worlds. These
  twelve tapes and their outcomes were seen in RN-1. This is a diagnostic
  comparison, not new independent validation evidence.
* New cases: n=8 and 16 with IID seeds 4,5,6,7. These eight tapes were not
  inspected or executed when choosing this protocol. Their separate actual
  AMP posterior workers use the same strong algorithm and limits as RN-1.

The generators, hidden independent-bit prior, edge observations, noise laws,
evaluation permutation and seed formulas are exactly RN-1's. Connected
training presents ten labels per oriented path edge. Evaluation presents all
n-squared ordered pairs once, with independent flip probability 1/10 in the
ideal generative law. The two disconnected cases omit edge (3,4), preserving
identical training while flipping all hidden bits in the second component.

All twenty FP cases run in fresh workers. For the twelve diagnostic cases,
reuse the already executed RN-1 FP and AMP posterior measurements, retaining
their original source identities. Do not rerun the unchanged baseline merely
to acquire a new timestamp. The eight new cases each run FP and the actual
posterior separately. Total: **28 new workers**. No case is dropped, no seed
is selected after seeing the new outcomes, and no parameter/cap is changed
to make a failure pass.

## 2. The declared solver/strategy change

The relation proposer still emits ordinary group SUMs, four PRODUCTs and
positive readouts from consistent untied empirical constraints. It now
chooses among the actual initializer values by exact pooled likelihood;
it does not inject an unrestricted fitted coefficient. The initializer
remains `(1,8)`. A chosen scale1 uses the actual initializer prefix for its
one-slot graph; a chosen scale8 uses both slots. Tied/inconsistent constraints
can still leave the proposer unresolved.

The bounded search attempts the same independently checked categorical upper
on the same full native grammar. When an actually compared candidate improves
the logged baseline but the upper is unattained, the v2 owned policy can
admit that candidate to new paired evidence. It issues no class-maximum proof
for this case. Current same-path crossings and full reachable CPU/CUDA
installation remain mandatory. The original incomplete class/frontier stays
retained and the final class decision must remain `UNRESOLVED`.

Registration uses the implemented v2 relation solver, v2 owned policy and
v2 installation proposition. Optional valid historical selections still
retain their exact old decision scope when actually proved. No external
callback, supplied graph family, hidden partition or posterior forecast
enters Runtime. The existing ordinary-data task law is unchanged.

## 3. Resource and information contract

Use RN-1's complete broad grammar, including unary SUM and pair lookup
competitors: node/SUM/PRODUCT/edge/slot caps are
`(2n+n^2+2, n^2+6, n^2+4, 4n^2+2n+12, 2)`. Base is `(1,1)`, total cap ten,
activation cap eight, and the complete source domain contains n-squared
one-hot context pairs. The search runs once at the training boundary with
its paid bounded-phase allowance.

Keep zero learning rate, ordinary update unit ten, grid16, reference integer
limit 32,768, packed cap 1 GiB and role work cap 10^13. Gradients, histories
and logical clocks still execute and survive. CPU tolerances are 2^-24;
CUDA state/probability tolerances remain 1/100. The actual RTX 3090 path
retains its 16 MiB arena, 32 MiB reservation cap, 4,096 output-cell and
131,072-byte phase limits, and distinct 24 GiB whole-board envelope.

Every worker is fenced before entry in a 4 GiB Windows job, with a 20-minute
observation timeout. Preserve actual build/device/job identity. The posterior
pays for its exact forest inference, materialized half table, gather and
single base/normalization pipeline. Its measured tensor peak and reservation
must fit the same 16/32 MiB limits. This value constructor is declared
separately from FP's native `(1,8)` path and confers no FP authority.

The two persistence rules retain bound3, epoch1, horizon n-squared, alpha1/4
per path, bet3/4 and the existing log/wealth precision; global alpha is 3/4
per root. No crossing is borrowed from RN-1 or from another new worker. No
cross-root significance/error-family claim is made. Seeded PRNG tapes remain
finite empirical evidence, not proof of ideal independence or freshness.

## 4. Fixed comparisons and interpretation

Compare frozen post-training candidate predictions, when actually built,
with the exact/AMP forest posterior at the **same training cutoff**. Score
previously unobserved relations, excluding diagonals and both orientations
of every observed training edge. Keep full-domain expected CE in binary64,
exact expected Brier and probability/classification diagnostics. Report
normalized retained AMP masses separately from raw single division.

Report deployed-stream scores separately: future ordinary labels can inform
persistence and installation, while the initial uniform deployment remains
live until a successful transition. Do not assign an absent candidate an
oracle score, replace policy loss with candidate loss, or count no install
within a finite run as statistical rejection.

Keep known-tape diagnostics separate from the new-seed sample. The latter is
a fixed small sample and supplies no population success-rate guarantee. A
hard correctly guessed relation can outperform a posterior in one realized
world; posterior optimality is prior-averaged conditional expected CE.
The disconnected pair checks whether uncertainty is still being hidden by
a training-optimal hard assignment. No forced PRODUCT or baseline-superiority
claim is planned.

Retain all search/proposal outcomes, actual construction/comparison counts,
proof counts, fresh alpha, installation cursors, phase audits and complete
run statuses. Failure outputs and their completed job record must remain
visible; preserve previously completed workers if reporting needs correction.
Unexpected execution/reporting failures provide no imputed model score or
completion authority. Do not silently rerun a failed case after changing its
budget or scientific parameters.

The known diagnostic AMP baseline is the canonical RN-1 journal committed
at `4d04595`, with original worker source `5b050c7`; verify its content and
case/count/device match before reuse. Save only the new compact worker
outcomes and a reference to that retained evidence, not duplicate datasets,
weights, full phase histories or the original baseline journal.
