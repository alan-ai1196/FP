# RN-3: native uncertainty across observed components

Preregister before target model execution. This follows RN-1/RN-2's
disconnected-world counterexample and the
[component symmetry construction](../../theory/proofs/COMPONENT_SYMMETRY_PROPOSAL.md).
Foundation R4, XVII.31 and ERC-1 remain frozen. Execute the v3 proposer only
after its exact and actual CPU/CUDA endpoint audits pass. Its uniform
component loop is a registered solver change within the existing native
grammar, value paths and v2 prospective policy; no semantic action is added.

## Scientific question

Can an actually constructed native program preserve uncertainty about
unobserved relative component flips, without importing posterior
coefficients? Does its frozen prediction improve the known equal-world
comparison, and how does fresh-evidence waiting affect actual deployment?

The prediction theorem is limited to the initialized one-hot endpoint. It
does not identify latent worlds, equate complete learners, or extend to
soft source mixtures. Finite IID uncertainty inside a component remains;
the method is not claimed to implement the full forest posterior.

An improved frozen predictor need not improve an adaptive deployed stream.
In particular, a hard guess followed by a fresh test can exploit later labels
and deploy in only one of the known worlds. Retain this possibility rather
than redefining success if the v3 deployed average is worse. Compare model
quality at equal information cuts; no deployed-algorithm superiority follows
from comparing against a posterior frozen at an earlier cutoff.
