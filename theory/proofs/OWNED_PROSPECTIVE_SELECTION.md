## 1. A training maximum is absent from the fresh-evidence theorem

Let a candidate be chosen from the actual revealed filtration at a legal
ordinary boundary tau. Its complete initialized/profiled reference and AMP
states, comparator, cursor, future scoring rule and alpha allocation are
owned at admission, before any scoring context arrives. The candidate need
not maximize its past empirical objective. Its construction can be adaptive,
and it can continue its registered causal learning after admission.

For either path, under its explicit conditional mean-null and predictable
gain bound, the already registered factor

`1 + lambda_j * Y_j / B_j`

has nonnegative value and conditional expectation at most one. Conditioning
on the whole admission filtration establishes the first step even when
the proposal search was adaptive or incomplete. Induction gives the same
supermartingale and anytime crossing bound. The implemented guarded lower
wealth inherits the existing enclosure argument. No training-maximum
premise occurs in this proof. Separate paths retain their own alpha debits,
boundedness, gains and current crossings; no evidence is copied between them.

This does not guarantee power, population identification, optimality among
unvisited programs, candidate reachability or successful physical transport.
It also does not supply a stochastic law to an unread deterministic tape.

## 2. Minimal installed-object provenance is already owned

The two existing persistence admissions retain the same complete starting
reference, binary64 (if registered) and CUDA (if registered) trajectories,
program and lineage IDs, comparator and ordinary cursor. Admission uses only
owned constructed candidates at a shared complete optimizer boundary. Their

The existing paired-result operation verifies equality of both admissions'
starting coordinates and schedules. Each current crossing separately checks
its continued complete learners against the Runtime's actual current states.
Installation additionally binds the pair's candidate to the requested target
and its comparator to the current deployed lineage. An identical graph with
a different newborn identity cannot inherit this pair.

These checks supply the required start/current provenance without a native
class-winner proof. No new signer, proposal certificate, mutable side state

remains an **optional additional assertion**: Runtime verifies that it is
owned, selected this exact lineage/comparator, and matches the fresh starting

silently ignored. Omitting that assertion grants only the narrower
prospective installation claim.

The complete physical transition is the existing serialized root/lease

device schema/extents/raw values, paid resources, retained shadows, search

Consequently a successful publication from the paired starts installs the
same continuously tested current learner. This statement is independent of
whether any historical training maximum was proved. It is not an equivalence
of old and new self-Compilers on all futures.

## 3. The native policy changes its decision, not its decision class

The registered v2 policy spends its fixed native search allowance. It still
returns every actual full-class completion proof under the existing rules.
If search is incomplete but has an actually compared candidate better than
the logged baseline, it stops that search allowance and admits the candidate
to new paired evidence. Without such a candidate it ends unresolved. The
policy receives no callback, supplied grouping, fitted coefficient or
externally selected candidate. Public control ports remain denied while
the complete owned policy is active.

The original full native grammar, profiles, baseline, objective, comparison
rows and unvisited frontier remain retained. No singleton class replaces the
grammar. If there is no class proof, installation can close the search's
execution but the final `RunDecision` still reports `UNRESOLVED` with no
proof. Successful deployment and unresolved optimization coexist as distinct
claims. The optional historical proof field is absent in that installation
receipt; it cannot be mistaken for a fabricated class maximum.

## 4. Remove the unnecessary free-fit prerequisite from the relation proposer

The native relation constructor still infers only consistent untied majority
constraints and emits the same typed group SUMs, four PRODUCTs and positive
readouts. Its task-specific alignment remains a registered proposal heuristic,
not an architecture decision class or latent-identification theorem.

For pooled majority/minority counts M,m and one available initialized scale
a, the emitted endpoint has likelihood

`((a+1)/(a+2))^M * (1/(a+2))^m`.

The v2 proposer compares those exact rational likelihoods over the registered
initializer prefix that fits the grammar's slot cap, with deterministic first
occurrence on a tie. It retains the chosen scale and all empirical counts.
It no longer calculates an unrestricted fitted coefficient and demands exact
membership in the initializer. Unanimous observations require no invented
infinite parameter: finite available values can still be compared. Native
construction, whole-domain safety, profiles and independent actual endpoint
scoring follow as before; the proposer alone grants none of them.

The Runtime prepays the additional bounded scale-comparison work. Every
arithmetic operation and exact comparison uses the registered integer limit;
insufficient work or arithmetic remains unresolved. This is a solver change
within existing value paths, not a new initializer or trained constant hidden
in syntax. Tied or inconsistent constraints, infeasible constructions and
unknown unvisited alternatives remain honest limitations of this proposer.
