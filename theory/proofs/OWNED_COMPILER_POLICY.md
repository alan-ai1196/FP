# The Compiler strategy belongs in complete Runtime state

Status: **implemented registered strategy; scoped state/filtration argument;
exact finite endpoint audit and actual CPU execution.** Foundation/ERC-1 stay

## 1. The missing owner

The preceding Runtime owns graph construction, search frontiers, ordinary
learners, numerical evidence, persistence and installation. Its manual audit
driver still chooses when to start search, which returned winner to admit,
when to inspect crossings and whether to install. Those tests establish the
individual endpoint transitions. They do not put the driver's changing
decision state into the self-Compiler's Omega.

Machine `packed-reference-payload-v7` adds an executable owned strategy. It
uses the existing native classes and four-path CPU protocol; it does not
introduce a new model primitive or a catalog of supplied architectures.
The existing manually controlled mode stays explicit and has a different
chi. Its scoped local results do not prove ownership of an external policy.

This also separates two error questions. Alpha is global across every
admission and installation in one actual Runtime root. A collection of
restarted roots is a different comparison family: individual per-root error
bounds cannot be presented as one shared family budget. The work here does
not invent a cross-process restart or refund protocol.

## 2. Fixed strategy, complete native classes

`ReferenceCompilerRuntime(..., policy=CompilerPolicy(steps))` accepts immutable
policy data. Each `CompilationStep` fixes an earliest ordinary cursor, a
registered native search name, an enumeration-step allowance, and the two
path-specific persistence rule names. The rule schedules must agree. The
constructor validates the strategy against the actual online registration.
No callback, graph, fitted value, winner ID, evidence record or running policy
state can substitute for this declaration.
An empty sequence is the owned ordinary baseline: it makes no compilation
actions, while retaining the same closed external control interface.

After each successful complete optimizer unit, the strategy visits its first
unfinished stage. Before the earliest cursor it waits. A new stage executes
the registered full native enumeration with its allowance. If it finishes
and selects a distinct candidate, Runtime admits reference and binary64
evidence separately at that same pre-context boundary. An incumbent winner
ends the stage without evidence allocation. An unfinished/uncertain search
ends UNRESOLVED, with its real frontier retained and closed.

At later complete optimizer boundaries the evidence stage reads its owned
pair. One failed/horizon-ended identity ends both current authorities without
refund. With two current crossings, Runtime executes the existing CPU install
checks. A successful installation ends that stage. Only a later complete
ordinary unit can visit the next stage. No new data event is created by these
control transitions, and no unread context or target is passed to them.

The allowance is a computation budget, not a completeness premise. Every
reference class proof keeps its existing exact decision class: fixed-state
empirical CE over the registered initializer/profile endpoints of the full
ordered grammar, plus the actual deployed baseline. It does not optimize
all parameter values, future trajectories or arbitrary strategy choices.

## 3. State, ports and resources

Omega now explicitly contains the immutable policy, its stage records and
execution flag. Each stage retains status, start/end cursors, owned search,
candidate, proposal and two evidence IDs, and its installation attempt.
The policy generation and packed object ID are retained too. Snapshots expose
these coordinates in `compiler_policy`; they accept no state replacement.

Policy records are ordinary owned packed objects. Updating one pays work and
allocates its replacement before releasing the previous buffer. Completed
stage records and all underlying search/data/evidence/install history remain
available. The fixed strategy reads current stage records and those owned
objects, never a removed policy version. Ordinary policy inspections also
pay the declared reference work. An optional live host binding covers the
same process-private metadata and workspace arena as all other Runtime work.
These reference-operation charges are not measured bit-time or GPU costs.

In policy mode, the only external methods are bounded context ingress,
prediction, target observation and passive snapshots. All 17 other current
control/authority methods are denied before argument decoding or mutation;
future methods default to denied. The fixed internal strategy can call the
same implementations, preserving their resource and authority checks.
This is the serialized registered Python machine, not a security sandbox
against arbitrary monkey-patching, reflection or native code.

The automatic phase follows a completed ordinary event, outside that event's
failure handler. Thus failure to retain policy progress cannot turn an already
received target back into an unread event. `OBSERVED_REFERENCE` still describes
the ordinary event; it is not a success flag for the entire Compiler run.
The owned policy record and halt state report the separate control outcome.

## 4. Composition argument

Assume the existing constructor, event, reference-class, CPU relation,
persistence and serialized installation contracts. Induct over actual
ordinary update boundaries of this registered strategy.

1. At initialization the validated policy is bound into chi, and its initial
   state has an owned paid buffer. No supplied running state is accepted.
2. A strategy choice is a deterministic function of its registration and
   the complete already revealed Runtime prefix. Its calls and state changes
   cannot interleave with context reception. Search and evidence starts
   therefore remain predictable before the next incoming context.
3. The native search methods retain coverage and comparison authority. The
   strategy cannot turn step exhaustion into grammar exhaustion, inject a
   cheaper program realization, or transfer an old current-optimum claim.
4. Every fresh path identity uses the existing nonrefundable global alpha
   ledger. Under its explicit stopped mean-null/stream-law assumptions,
   the old conditional error proof applies to the enlarged owned filtration.
   A failed second admission leaves the first allocation spent. For one
   root, `sum(admitted alpha) <= alpha_total` still bounds the union of its
   relevant false crossings. Neither deterministic audit tapes nor restarting
   a root establish that stochastic assumption or a larger family guarantee.
5. Installation binds the actual selected proposal to its current four
   trajectories and separately crossed statistics. Its frame schema now
   includes the policy coordinates. The completed policy record is prepared
   under the installation workspace owner, then transferred with the other
   objects in the **same single root/lease publication**. The previous policy
   buffer is released by that same transaction. There is no allocating
   success bookkeeping after publication; the existing prepared ordinary
   result can return after the execution flag is cleared.

Policy-state storage refusal after an action halts the owning execution.
An unfinished action cannot be retried with a fresh ID or refunded budget.
Checked search/evidence/install uncertainty that can be recorded instead ends
that stage UNRESOLVED and permits the declared ordinary continuation.

Native resource-premise loss must also escape nested public calls. The common
host boundary was insufficiently explicit about calls made inside another
endpoint's broad exception handler. All such handlers now propagate
`HostExecutionUnresolved` as well as MemoryError, without allocating cleanup.
The host exception is distinct from argument/graph `ContractError`; otherwise
an earlier checked-argument handler could misclassify lost physical premises
as graph inadmissibility. A construction fault exercises that distinction.
The audit loses a native observation inside installation's paired-evidence
read: the last ordinary event, spent alpha and unfinished install remain,
while the first host halt marker and old deployment are preserved.
