# Owned CUDA installation by resident identity transport

Status: **scoped transition proof and actual RTX 3090 endpoint audit.**
The registered machine is serialized CPython, the private default-stream
CUDA prefix and its prepaid tensor arena, with the existing packed host
payload/lease model. This proves one executable installation transition.
It does not establish a current global optimum, total-device resource
enforcement, concurrent/crash-safe publication or a complete target release.
Foundation R4, XVII.31 and ERC-1 are unchanged.

The normative obligations are [FP_THEORY.md XIV--XVI, XVIII](../../FP_THEORY.md)
and [ERC-1 sections 2--5](../../EXPERIMENT_RESOURCE_CONTRACT.md). The proof
composes [owned native selection](ORDERED_NATIVE_REFERENCE_CLASS.md),
[continuous device construction](OWNED_CUDA_PREFIX.md),
[current range and fresh same-path evidence](OWNED_CUDA_PERSISTENCE.md)
and the existing [CPU root/lease transition](OWNED_CPU_INSTALLATION.md).
It adds no semantic architecture action.

## 1. Why identity transport is physically available

Before installation, the candidate and incumbent already have independently
executed complete CUDA learners in the **same actual backing arena**. Native
initialization, any registered profile and every fresh ordinary update have
paid their storage and execution costs. Construction never frees the
incumbent to make the candidate fit.

The arena's entire allocation and native allocator reservation have belonged
to both registered resource roles since arena admission, once globally.
Installation changes which candidate is deployed; it does not need to move,
recast, reset or free either CUDA learner. Region `owner` labels record the
phase that initialized an extent. They are retained provenance, not exclusive
deployment/Compiler role leases that must be relabelled at installation.

This is a consequence of this already registered physical realization, not
a theorem that every device layout has free installation. A different arena,
device, representation or role scheme requires its own reachable transport.
Current installation performs paid device-to-host readback checks. It does
not claim zero physical work or absence of all data copies; the installed
numerical state itself keeps its original CUDA objects and extents.

## 2. Owned authority has three distinct premises

`CudaPrefixContract(install=CudaInstallContract(...))` fixes the implemented
transport and its work/workspace roles in the immutable run manifest before
construction. The public `install_cuda` port accepts only owned candidate,
proposal-proof, reference-identity and CUDA-identity names. Helpers expose
passive records and private checks, with no supplied-state signer.

At proposal cursor t0, an owned completed native search selected this exact
lineage from its registered initializer/profile class plus actual baseline.
Its proof is historical selection provenance at t0. Fresh learning may change
the winner's parameters; installation at t need not and does not prove that
the trained successor remains a current maximum of that constructor class.

Both current reference and CUDA persistence identities must independently
cross, with matching complete starting trajectories, ordinary cursors and
epoch schedules. Their reference starts must be exactly the selected row
and comparator at t0. CUDA starts bind actual retained device phases. Alpha,
wealth and a proposal cannot be inherited by a same-graph newborn.

Finally the old deployment and target must be at a full optimizer boundary,
with current complete reference/CUDA state relations. Optional CPU binary64
learners also retain their own checked complete states. These three premises
compose historical selection, current conditional evidence and an executed
physical transition; they do not compose into `CERTIFIED_COMPLETE`.

## 3. Complete device frame and publication

Runtime checks its fixed root schema; after paid control admission and
preparation work it checks the private CUDA-prefix/arena field schemas. An
unknown job/cache/device coordinate cannot silently inherit this transition
proof. The arena must have no active phase and its registered default stream
must report quiescence. Allocation history and settings must still match
the original arena contract.

For every retained current candidate, the device phase must identify that
same candidate/program and local learner cursor. Each actual theta, gradient
and delayed queue must belong to an initialized typed arena extent **before
any numeric readback**. Full shape/dtype/device/finite-state validation and
raw-state equality then compare it to its owned completed phase record.
This covers inactive retained shadows at their own clocks as well as the
two active installation lineages.

The private preparation witness retains the original prefix, contract,
arena, backing tensor, all current/staged/predicted maps, every phase/value
object and the complete arena snapshot. Runtime prepares the same atomic
packed-buffer lease transaction as CPU installation. Before publication it
rechecks the device witness: exact object identity, bindings, raw current
states, shapes/offsets, initialized extents, phase history, allocation counts
and residency are unchanged. The compact receipt binds current states and
extents plus retained-history counts; full history stays in its existing
owned records rather than being duplicated into the receipt.

The subsequent [actual device binding](WHOLE_BOARD_CUDA_RESOURCES.md) extends
this frame with its fixed private field schema and identical binding/initial
identity objects. Actual runtime/driver/UUID/capacity checks accompany arena
verification; the whole-board resource envelope stays shared by both roles.

| Complete coordinate | Published effect |
|---|---|
| Exogenous cursor, contexts, targets and data-use history | Preserved; no event is consumed by installation |
| All reference and optional binary64 learners | Same complete records and actual buffers, apart from declared role ownership |
| All current and historical CUDA learners/forecasts | Same resident objects, raw current values and arena extents; no numerical transport |
| Deployed lineage | Target becomes deployed; incumbent remains a shadow under a fresh packed-buffer owner |
| CUDA arena and resource roles | Same backing allocation, lifetime counters and whole-arena charges to both roles |
| Search/frontier state | All continuing searches close; original rows, frontiers and history remain |
| Persistence | All live/crossed identities become unresolved; no rebase, alpha refund or erased history |
| Installation and resource history | Paid attempts, work, peaks, lease transfer and receipt are retained together |
| Remaining root state | Carried by the complete root frame; no omitted scheduler or learner coordinate |

All fallible preparation, readback, checks and result construction precede
the single `self.__dict__ = next_root` publication. The CUDA prefix object
itself is carried unchanged. The implementation uses the same private root
transaction for the CPU and CUDA public ports; the CPU port still refuses
a CUDA-bearing root.

**Scoped transition theorem.** Under the declared serialized machine and
trusted private executor/arena, a successful `INSTALLED_CUDA` publication has
exactly the selected continued complete learners at the original ordinary
cursor and exactly the frame above. The current numerical relation survives
by identity; no additional approximate-equivalence composition is required.
This is a registered installation transition, not equivalence of the entire
old and new self-Compiler on every future task.

## 4. Failure and resource statements

The existing fixed packed-machine preparation debit is
`4096 + 16*retained_buffer_bytes + 1024*(objects+candidates+identities+searches)`,
in the registered work role, with additional current bridge work. It is paid
before transport inspection. Prepared invalidations, search closures and the
receipt incur actual host-payload residency while the old records remain.
Insufficient immutable byte/work caps therefore refuse a candidate whose
already resident model itself fits. This metric is not elapsed GPU time,
complete host instruction work or a driver/context memory bound.

A benign failed preparation leaves old deployment, learner objects,
persistence and searches in place. Attempt IDs, revision, work, peak use,
retired preparation IDs and diagnostics remain spent. New paid attempts use
fresh physical IDs. A prepared receipt is not installed authority.

Observed loss of actual device state, shape, initialized extent or arena
premises is different: Runtime halts and revokes all live old crossings.
Leaving numeric state unpublished does not make corrupted old state safe.
Unexpected failures retain their original exception classification. An
allocation failure follows the existing terminal host-allocation guard.
The audit's pending external kernel is an injected violation of quiescence,
not a free legal asynchronous job admitted by this serialized interface.

## 5. Executed evidence and remaining target work

Run `python -B scripts/audit_cuda_installation.py --write`. Each CUDA case
uses a fresh allocator process. Complete native classes have 35, 774 and 124
members; their installed continuations contribute respectively 151, 870 and
240 independent exact-rounded device phase checks, alongside the same
counts of independent CPU binary64 checks. The 774-member case installs
nonzero trained theta at cursor 18. The recurrent class preserves both
positions of each delay queue. Observational line tracing sees one complete
old/new publication, with identical device objects and storage throughout.
A separate 35-member run omits the optional CPU binary64 learners entirely;
installation and 151 CUDA phases still pass on the four reference/CUDA paths.

Two further 35-member selections install in one Runtime at cursors 22 and
38. The second comparison uses the actual new baseline, starts fresh
identities at cursor 24 with unit wealth and retains both receipts. The four
alpha allocations spend the registered 3/4; a third admission is refused.
Independent rounded replay checks 306 phases through later continuation.

Adversaries cover false proof/path IDs, same-graph newborns, partial optimizer
units, paused searches, unknown state coordinates, pending device work,
late preparation failure and a legal paid retry. Actual immutable byte and
work caps reject preparation. A tensor shape mutation preserving raw values
still makes old crossings unusable. A view extending beyond its initialized
extent is refused before numeric readback. These mutations are explicit
fault injections, not spontaneous hardware failures.

The compact record is
[`FP_CUDA_INSTALLATION_AUDIT.json`](../../evidence/minimal/FP_CUDA_INSTALLATION_AUDIT.json).
The existing complete CPU installation, owned-policy, host-allocation and
finite-run regressions accompany the shared transaction change. The full
owned-policy invocation reached its last, bounded section, where the old
fault hook still named the former public transaction body. Retargeting it
to the shared private transaction restores that intended fault; the bounded
section then passes in its actual 64 MiB job. No production resource limit
or failure rule changed. CUDA prefix and persistence regressions also pass.
This does not reissue the frozen CPU release.
