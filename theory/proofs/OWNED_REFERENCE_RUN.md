# Execution completion is a separate claim from a completed decision

Status: **implemented single-root reference protocol; conditional composition
argument; exact endpoint/model checks and actual bounded CPU execution.**
Foundation/ERC-1 remain frozen. Runtime is NOT FROZEN and science is HOLD.

## 1. The two propositions

An ordinary `OBSERVED_REFERENCE` result says that an event reached its
registered learner boundary. It does not say that the following Compiler
action or the complete run succeeded. Conversely, finishing all registered
ordinary events need not finish a useful structural comparison: search work
may be exhausted, evidence may never cross, or a later policy stage may never
reach an eligible optimizer boundary.

The v7 strategy already distinguishes event failure from policy failure. Its
returned event result alone is therefore an insufficient run report. Machine
`packed-reference-payload-v8` makes the run binding, final classification and
termination of authority part of the owning Runtime. This is a protocol over
the existing grammar and policy, not a new semantic architecture operation.

## 2. Immutable binding is owned data

Runtime assembles one `ReferenceRunManifest` from the validated construction,
initial Program, ordinary/data/learner/search/evidence/CPU registration, host
contract and policy. It also records the fixed machine/initializer identities,
actual Python implementation/version and reference/CPU arithmetic. The CPU
declaration states binary64 storage and operations, 53-bit precision,
normal exponent range [-1022,1023], gradual subnormals, ties-even rounding,
ordered separate operations and exact primitive checks. Actual target AMP is
explicitly UNRESOLVED. No caller manifest, completion record or callback is
accepted as an authority input.

The whole immutable declaration, including the initial baseline, determines
chi. Runtime retains its exact packed bytes under its information owner and
pays work/residency before constructing the deployed learner. Existing
semantic P/S/edge/slot caps, source domain and normalizer/activation caps,
ingress/query widths, reference integer limits, optimizer and persistence
rules are constituent fields; they are not replaced by free-form scope text.
The CPU install frame schema includes the manifest and run-closure coordinate.

Recording declarations has a real consequence: changing a numeric budget can
change the declaration's own encoded length and startup work. Two older audit
fixtures assumed those costs were independent of the cap. They now calibrate
new immutable diagnostic roots until the actual encoded budget stabilizes,
then test the exact boundary. No running limit is mutated and no declaration
cost is waived. These diagnostic roots are not one statistical claim family.
CPU installation and run closure check the same fixed complete-root field
schema; an unregistered future job cannot inherit either frame argument.

## 3. Predetermined horizon and terminal authority

In owned-policy mode, N is the length of the already registered ordinary
observation schedule. After each successfully published ordinary event the
existing strategy runs at its registered optimizer boundary. Runtime then
considers run closure. Closure requires cursor N, no halt, no pending target,
no active ingress and no executing policy action. It creates no observation
or extra optimizer commit. At a partial final optimizer unit, the actual
gradient accumulator and count remain intact; the strategy receives no
invented final boundary.

Runtime prepays the report scan and retention. Its closure records:

- final cursor/deployment, policy generation and each stage's outcome;
- every search's exact registered decision class, comparison cursor/base,
  current search status and separately retained historical class proof;
- retained native graph counts, with SUM edges and both square incidences;
- exact-reference and CPU prediction diagnostics from retained ordinary and
  profile traces, including minimum nonzero activation and maximum normalizer;
- the partial optimizer count and nonrefundable alpha spent by this root.

Diagnostic numerator/denominator bit lengths describe rational encodings of
retained prediction values. They are not hardware significand widths, future
bounds or a liveness-optimal memory claim. Internal search/range scratch is
not an additional scored prediction trace. Full range enclosures, exact
normalizers/stored masses, actual raw finite encodings, resources, learners,
filtration and historical evidence remain in the complete Runtime snapshot.
The report consists of its `run` header **and that complete snapshot**; its
resource ledger includes the manifest and final report themselves. Live
native resource observations are still observations of the bound process,
not equivalence classes for every future kernel behavior.

Only after the closure buffer exists does Runtime publish the closure pointer.
All 22 non-diagnostic public ports then deny before argument decoding and
without new recorded work/history. Existing search/evidence records remain
historical data even if their old local status says ACTIVE or crossed. No
object, alpha allocation or unfinished stage is erased/refunded. The root's
terminal boundary removes their continuation authority. Snapshots remain
passive diagnostics and may themselves fail to allocate.

This is not a claim that open and sealed states are behaviorally equivalent.
The stop rule is fixed at registration and executed at its stated horizon;
there is no claim-preserving erasure that needs a new equivalence theorem.

## 4. Completion, historical truth and failure

`SEALED_REFERENCE_STREAM` means this finite reference stream and its terminal
protocol completed. Each unfinished stage is reported UNRESOLVED, preserving
its actual stage record. Historical finite-class completion is also distinct
from current search authority: installation invalidates the latter but cannot
erase the former. The report retrieves the owned historical proof by its
search identity, not by a current authorization field that installation has
already cleared. A historical winner is not recertified at its trained endpoint.

No report issues `CERTIFIED_COMPLETE`. The exact existing class is fixed-state
empirical CE on registered initializer/profile endpoints of the complete
ordered grammar plus the actual deployed baseline. There is no assertion of
universal parameter, trajectory, policy or physical-resource optimality.
Missing host binding explicitly limits execution to packed-payload accounting.
Manual endpoint mode is reported `MANUAL_PARTIAL` and does not silently acquire
the owned strategy's terminal protocol.

Assume the existing construction/event/search/paired-CPU/installation
contracts. Their state induction gives all successful ordinary prefixes and
the post-event policy action. The closure preconditions and last-pointer
publication establish the registered final boundary. Subsequent public calls
cannot resume a learner, re-admit evidence, construct or install. Thus a
retained completed-stream claim and an unresolved structural decision can
coexist without inventing either a negative certificate or fresh data.

Closure is a **separate transition after installation**, not allocating
installation-success bookkeeping. If report work, arithmetic or retention
fails, Runtime halts and its run status is `HALTED_UNRESOLVED`. The ordinary
event and any already published CPU install remain completed facts. The audit
injects both a resource refusal and MemoryError at report retention after an
installation at cursor 22: the new deployment, completed policy, target,
receipt and alpha all survive, but no run closure exists. Native premise loss
and allocation failure propagate through the common terminal boundary without
allocating cleanup or rewriting the first host failure cause.

A Runtime snapshot cannot prove its operating-system process has exited
successfully or cover future export work. The bounded audit separately checks
the actual launched process identity, exit status, timeout and final job
counters. This is one scoped diagnostic run, not restart/family-error support.
